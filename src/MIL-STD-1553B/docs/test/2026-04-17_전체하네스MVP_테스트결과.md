## 3. 테스트 시나리오
- 네이티브 15건:
  Command/Status 해석, HealthSnapshot 추적, BC timeout/retry, Bus A/B 전환, BM 저장, `RT -> BC`, `RT <-> RT`, Mode Code 2종, 세션 중심 C ABI, `BufferTooSmall`
- Host / Interop 22건:
  JSON 검증, 세션 제어, telemetry 조회, JSONL export, JSON marshalling, status code 변환, `BufferTooSmall` 재시도, runtime layout smoke test, DLL 누락 / 잘못된 바이너리 / 엔트리 포인트 누락, `dotnet build/publish` one-shot packaging output

## 4. 입력 조건
- 네이티브는 fake adapter / fake clock 기반 입력을 사용했다.
- Host / Interop는 fake low-level native API와 실제 빌드한 `MilStd1553.Native.dll`을 함께 사용했다.
- 실제 DLL 적재와 packaging 테스트는 `MILSTD1553_NATIVE_RUNTIME_ROOT` 또는 임시 output 루트 아래 `runtimes/win-x64/native` 구조를 사용했다.

## 5. 기대 결과
- 네이티브 코어가 MVP 범위의 BC / RT / BM 메시지 흐름을 안정적으로 처리한다.
- Host / Interop가 DTO 전달, 예외 변환, report export, runtime loader 경계, one-shot packaging 경로를 안정적으로 처리한다.
- 실제 DLL 적재 성공 경로와 운영성 실패 경로를 함께 드러낸다.

## 6. 실제 결과
- `tests/native/run_tests.ps1` 실행 결과 네이티브 테스트 15건이 모두 통과했다.
- `dotnet test tests/dotnet/MilStd1553.Host.Tests/MilStd1553.Host.Tests.csproj` 실행 결과 Host / Interop 테스트 22건이 모두 통과했다.
- 실제 `MilStd1553.Native.dll`을 빌드한 뒤 runtime layout 경로로 배치해 smoke test가 성공했다.
- DLL 누락 / 잘못된 바이너리 / 엔트리 포인트 누락 시나리오는 `NativeLibraryLoadException`으로 분류됐다.
- `dotnet build/publish src/dotnet/MilStd1553.Interop/MilStd1553.Interop.csproj` 1회 결과 폴더 아래 `MilStd1553.Interop.dll`, `MilStd1553.Host.dll`, `runtimes/win-x64/native/MilStd1553.Native.dll`가 함께 생성되는 것을 확인했다.
- 루트 `README.md`에 적은 quick guide 명령(`dotnet build`, `dotnet publish`, `dotnet test`, `tests/native/run_tests.ps1`)을 다시 실행해 문서와 실제 결과가 일치함을 확인했다.
