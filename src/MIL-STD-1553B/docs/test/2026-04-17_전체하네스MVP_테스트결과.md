## 5. 기대 결과

- 네이티브 코어는 MVP 범위의 BC / RT / BM 메시지 흐름을 안정적으로 처리해야 한다.
- `NativeSessionApi`는 detached stub이 아니라 실제 세션 런타임 facade로 동작해야 한다.
- `OpenSession` 이후 첫 번째 `PollTelemetry`는 초기 schedule pass의 `MessageFrame`을 반환해야 한다.
- `SwitchBus` 이후 다음 `PollTelemetry`는 `BusSwitch` 이벤트를 반환해야 한다.
- Host / Interop는 DTO 전달, 예외 변환, report export, runtime loader 경계, one-shot packaging 경로를 안정적으로 처리해야 한다.

## 6. 실제 결과

- `powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\native\run_tests.ps1` 실행 결과 네이티브 테스트 34건이 모두 통과했다.

- `dotnet test tests/dotnet/MilStd1553.Host.Tests/MilStd1553.Host.Tests.csproj` 실행 결과 Host / Interop 테스트 34건이 이전 사이클에서 모두 통과했다.
- 2026-04-18 RT ↔ RT timing 사이클에서는 `dotnet test tests/dotnet/MilStd1553.Host.Tests/MilStd1553.Host.Tests.csproj --no-build --filter "FullyQualifiedName~NativeHarnessClientEndToEndTests"` 기준 영향 범위 smoke 5건을 다시 확인했다.
- 2026-04-18 Mode Code tranche 1 사이클에서도 같은 영향 범위 smoke 5건을 다시 확인했다.
- `NativeSessionApi`는 시나리오 JSON을 파싱한 뒤 `BusMonitorService`, `SimulatorVendorChannel`, `VendorSdkBusAdapter`, `BusControllerService`를 조립하고, 초기 BC schedule pass를 1회 수행한다.
- `NativeSessionApiManagesSessionLifecycle`와 실제 runtime layout smoke test는 첫 번째 `PollTelemetry`에서 `MessageFrame`, `SwitchBus` 이후 두 번째 `PollTelemetry`에서 `BusSwitch`, 마지막 `PollTelemetry`에서 `[]`를 확인했다.
- `PollTelemetry`는 `BufferTooSmall`일 때 pending telemetry를 유지하고, 성공적인 직렬화 이후에만 cursor를 전진시켰다.

## 8. 실패 케이스

- 이번 사이클의 Red 단계에서는 네이티브와 Host end-to-end smoke test를 먼저 강화해, 기존 stub `NativeSessionApi`로는 “초기 `MessageFrame` telemetry 반환” 조건을 만족하지 못하게 만들었다.
- 이후 실제 세션 런타임 조립과 초기 schedule pass를 구현한 뒤 Green으로 전환했다.

## 9. 리스크

- 실장비용 `IVendorChannel` concrete binding은 아직 없다.
- RT ↔ RT timing / intermessage gap fidelity는 현재 최소 `40us` gap 보정 baseline까지가 범위이며, 더 깊은 physical timing 모델은 후속 backlog로 남겨 둔다.
- rich UI가 필요해지면 현재 CLI 기준 진입점을 별도 Presentation 레이어로 확장해야 한다.

## 10. 후속 조치

- 다음 내부 구현은 Host JSONL `schema v1` exporter / replay reader 도입이다.
- 실장비용 벤더 SDK가 확보되면 `IVendorChannel` concrete binding과 실장비 smoke test를 추가한다.
- RT ↔ RT fidelity 향상, Mode Code 2차 묶음, richer replay / report presentation은 deferred backlog로 유지한다.
