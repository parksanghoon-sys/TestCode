# 2026-04-18_잔여확장설계_테스트결과

## 1. 테스트 대상

- `docs/design/2026-04-18_잔여확장설계_설계검토.md`
- `CURRENT_PLAN.md`
- `TODOS.md`
- `DECISIONS.md`

## 2. 테스트 시나리오

1. 남은 설계 항목이 중복 없이 하나의 기준선으로 정리되었는지 확인한다.
2. 기존 MVP / mock / RT ↔ RT 설계와 충돌하는 새 결정이 없는지 확인한다.
3. 후속 구현 항목이 `Current TODOs` 또는 `Deferred Backlog`로 handoff 가능한 수준인지 확인한다.

## 3. 정상 흐름

- 실장비 binding, RT ↔ RT 고도화, Mode Code 확장, replay/report schema, GUI 방향이 문서에 모두 반영되었다.
- CLI canonical 경로와 현재 Host / Interop 책임 분리가 유지된다.
- 설계 결정이 `DECISIONS.md`와 상태 문서에 일관되게 남는다.

## 4. 비정상 흐름

- 없음. 이번 사이클은 코드 변경이 없는 설계 정리 작업이다.

## 5. 타임아웃 / 재시도

- 실행 검증 없음. 다만 설계 문서에서 timeout / retry 책임이 계속 `Application`에 남는 것으로 확인했다.

## 6. Bus A/B 전환

- 실행 검증 없음. 다만 실장비 binding 설계가 현재 `SelectBus`와 automatic failover 책임 경계를 유지하는 것으로 확인했다.

## 7. BC → RT

- 실행 검증 없음. 기존 설계를 유지하고 후속 구현에서 회귀 검증하도록 계획만 고정했다.

## 8. RT → BC

- 실행 검증 없음. 기존 payload 보존 규칙을 후속 구현의 회귀 조건으로 유지했다.

## 9. RT ↔ RT

- 실행 검증 없음. deeper physical timing은 별도 planner / policy로 분리한다는 설계 기준을 확정했다.

## 10. Mode Code

- 실행 검증 없음. 1차 Mode Code 묶음과 2차 묶음의 우선순위를 문서로 고정했다.

## 11. 로그 확인 포인트

- 실행 로그 없음.
- 문서 기준으로는 JSONL schema v1에 `schemaVersion`, `recordType`, `sessionId`, `sequence`를 추가하는 방향을 확정했다.

## 12. 결과 요약

- 설계 문서, 상태 문서, 의사결정 기록의 정합성을 검토했다.
- 코드 변경이 없으므로 build / test 명령은 실행하지 않았다.
- 남아 있던 설계 미확정 사항은 외부 SDK 입력 자체를 제외하면 모두 닫힌 상태다.
