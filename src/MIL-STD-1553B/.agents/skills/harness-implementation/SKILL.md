# MIL-STD-1553B 하네스 구현 스킬

## 목적

이 스킬은 설계 검토 문서를 기준으로 실제 구현을 진행한다.  
반드시 **설계 검토 이후**에만 사용한다.

---

## 시작 전 체크

아래가 준비되지 않았다면 구현을 시작하지 않는다.

- 관련 설계 검토 문서가 존재하는가?
- 요구사항과 제외 범위가 정리되었는가?
- C++ / C# 책임 경계가 정리되었는가?
- 먼저 작성할 실패 테스트(Red)가 정리되었는가?

---

## 반드시 지킬 규칙

- **설계 검토 → 구현 → 테스트** 순서를 깨지 않는다.
- 구현은 반드시 **TDD 3색 원칙**에 따라 진행한다.
- 구현만 하고 끝내지 않는다. 테스트와 문서를 함께 갱신한다.
- **클린 아키텍처** 를 위반하지 않는다.
- **OOP 원칙** 을 지킨다.
- **모든 주요 타입과 메서드에 한글 XML 주석** 을 작성한다.
- 구조를 흔드는 임시 코드, 하드코딩, 역할 혼합을 피한다.

---

## 구현 절차

1. 설계 검토 문서를 읽고 작업 범위를 다시 확인한다.
2. 먼저 실패 테스트를 작성한다.
3. 최소 구현으로 테스트를 통과시킨다.
4. 리팩터링으로 책임을 정리한다.
5. XML 한글 주석을 보강한다.
6. 문서와 테스트를 함께 갱신한다.

---

## C++ 구현 지침

- 벤더 SDK 연동은 Infrastructure에 격리한다.
- 워드 파싱, 메시지 구성, 상태 해석은 가능한 한 도메인 모델로 끌어올린다.
- RAII를 기본으로 한다.
- raw pointer 남용을 피한다.
- 예외 또는 오류 코드는 일관된 정책으로 표현한다.
- 헤더 공개 API에는 XML 스타일 한글 주석을 반드시 작성한다.

### C++ 주석 예시

```cpp
/// <summary>
/// 수신한 1553 커맨드 워드를 도메인 객체로 변환합니다.
/// </summary>
/// <param name="rawWord">원본 16비트 워드입니다.</param>
/// <returns>파싱된 커맨드 워드 객체입니다.</returns>
CommandWord Parse(std::uint16_t rawWord);
```

## C# 구현 지침

- 상위 오케스트레이션과 UI는 유스케이스를 통해 도메인을 호출한다.
- DTO와 ViewModel의 책임을 혼합하지 않는다.
- 프로젝트가 허용하는 범위에서 최신 C# 문법을 우선 사용한다.
- async 흐름은 취소와 타임아웃을 고려한다.
- public API에는 XML 한글 주석을 반드시 작성한다.

### C# 주석 예시

```csharp
/// <summary>
/// RT 상태 조회 시나리오를 실행합니다.
/// </summary>
/// <param name="request">실행 요청 정보입니다.</param>
/// <param name="cancellationToken">취소 토큰입니다.</param>
/// <returns>실행 결과입니다.</returns>
public Task<ScenarioResult> ExecuteAsync(
    ScenarioRequest request,
    CancellationToken cancellationToken)
{
    ...
}
```
